# Recoverable Ark commissioning batches

Implement the authorized Ark commissioning transaction, replacing free phase clicks. This is one technical slice of the active E2E goal, not the finished endgame or release.

Four narrative phases have six module steps in existing arkPhase order: engineering/calibrate (4 calibration_frame + 2 power_regulator), arcane/stabilize (2 containment_seal), nature/stabilize (2 ecosystem_capsule), logistics/provision (2 routing_matrix), habitation/provision (8 ration_bundle), exploration/chart (1 horizon_chart). All IDs use entrelumen namespace. Preserve legacy arkPhase 0..6 exactly: secured steps stay credited. Record the current step's partial deposits in schema 2 SavedData; schema 1 loads with an empty partial ledger. Reject future schemas. No change to historical quest/project IDs or rewards.

Server actions require current campaign identity, expected step, act VI, all six module milestones and all six module blocks in the existing bounded controller volume. Interactions inspect on ordinary use, deposit on crouched use with an empty main hand. Consume only available required items from the player's ordinary inventory/offhand, capped by remaining costs. Preserve surplus, unrelated items and physical blocks. Each successful partial/full deposit marks SavedData dirty. Never extract remote inventories, continuously scan, decay offline or pay a reward. A completed step cannot consume again for the same expected step. Missing structure, wrong/stale team, wrong step or archived campaign rejects without consumption. Show bilingual current module, accepted/missing quantities and explicit deposit instructions.

Pure domain: ArkCommissioning has immutable Step(module, phase, requirements), STEPS, eligible(Campaign), missing(Campaign), and deposit(Campaign,int expectedStep,Map<String,Integer> inventory,Consumer<Map<String,Integer>> consume) returning boolean. Campaign adds arkDeposits map, copied deeply. ArkActions.deposit(ServerPlayer,UUID expectedCampaign,BlockPos controller,int expectedStep) routes authoritative runtime changes and returns boolean. ArkActions.inspect(ServerPlayer,BlockPos) displays the ledger. ArkControllerBlock uses those routes. Root owns integration and translations; domain worker owns only listed pure domain/persistence files; runtime verifier owns only RuntimeGameTests.java. No redelegation or concurrent builds.

Acceptance: exact partial consumption and caps; resume after NBT/disk serialization; independent personal/team ledgers and restored personal snapshot; rejected replay and stale team; missing-module rejection without loading absent chunks; actual vanilla useItemOn controller path; all blocks/surplus preserved; EN/ES key/placeholder parity. Tests do not prove survival acquisition, visual acceptance, final exploration, pacing, performance, publication or the six full module experiences. Those stay open in the parent plan. Existing approved private API access is unrelated and unnecessary for this slice.
