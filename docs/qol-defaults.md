# Player-facing QoL defaults

These source defaults are for the next installation/restart. The running ENTRELUMEN profile was read only. No ATM10 configs were used. No mods, gameplay bindings, JourneyMap settings or server claims settings were changed.

| File / key | Shipped value | Effect and evidence |
|---|---|---|
| `config/fancymenu/options.txt`, `customization.modpack_mode` | `true` | Suppresses FancyMenu authoring overlays and its authoring hotkeys. Official [FancyMenu modpack documentation](https://docs.fancymenu.net/docs/en-US/modpacks) explicitly recommends this for distributed packs. |
| Same file, `customization.show_customization_overlay` | `false` | Keeps the toolbar hidden as the explicit stored preference, also if modpack mode is later disabled. Exact typed `B:key = 'value';` format was read from ENTRELUMEN's generated FancyMenu 3.9.12 config. |
| Same file, `tutorial.show_welcome_screen` | `false` | Prevents the authoring welcome dialog on a fresh installation; documented by FancyMenu and present in generated config. |
| `config/ftbchunks-client.snbt`, `minimap.enabled` | `false` | Disables only the FTB Chunks minimap. Exact nested key and boolean format were read from ENTRELUMEN's generated FTB Chunks 2101.1.21 config. Claims, full-screen map, waypoints and permissions are not overridden. |
| `config/ftbchunks-world.snbt`, `require_game_stage` | `true` | FTB Chunks 2101.1.21 shows its map and minimap only to players with the `ftbchunks_mapping` stage (`FTBChunksWorldConfig.playerHasMapStage`, synced server config). The companion gives the stage to every player outside the Envés and removes it inside, so the dungeon's fog map is the only map there (docs/design/dungeon-enves.md). |
| `config/ftbxmodcompat.snbt`, `stage_selector` | `"vanilla"` | FTB XMod Compat 21.1.11's default hands FTB Library's game stages to KubeJS whenever KubeJS is loaded (`generic/gamestages/StagesSetup`). `vanilla` keeps FTB Library's own entity-tag stages (`EntityTagStageProvider`), the ones the Envés map switch above uses. The other keys keep their defaults (docs/design/mod-pingpong.md, FTB Filter System and FTB XMod Compat). |

Only the intended keys are supplied. Other mod options retain their defaults. Source inspection found **FTB's generated minimap already disabled** and FancyMenu's welcome already dismissed; therefore duplicate minimaps were a hypothesis, not a verified current defect. Shipping these explicit defaults makes fresh installs consistent.

## Player customization

Normal Minecraft controls and JourneyMap controls remain editable. FancyMenu's authoring-only hotkeys are disabled by modpack mode. To author a local menu again, close the game, set `modpack_mode` to `false` and `show_customization_overlay` to `true`, then relaunch. To hide it again, restore the shipped values.

FTB Chunks' generated config documents `local/ftbchunks-client.snbt` as the persistent player override, which pack updates do not overwrite. A player wanting its minimap can put `{ minimap: { enabled: true } }` there. The pack does not write this personal file. They may also change their normal navigation keybindings through Controls.

## Verification evidence and remaining check

The source keys and value syntax were checked against the configuration generated by this pack's own client, and FancyMenu mode/welcome behavior against its official documentation. The active profile was not modified. No rendered verification is claimed.

After the integrator installs the files with the client closed:

1. Start a fresh client profile: no FancyMenu welcome window or editor toolbar should appear on the title screen.
2. Open a world: JourneyMap remains available, with no FTB minimap in the HUD.
3. Open the FTB Chunks full map and claim controls: both remain usable; confirm an existing claim remains protected.
4. Change a normal control binding and confirm it persists across restart.
5. Optionally test the documented local minimap override, then restore the tester's chosen preference.

Do not overwrite a running client's config: it may save its in-memory values over the installed defaults on exit. Installation of these source defaults and rendered confirmation belong to the integrator.
