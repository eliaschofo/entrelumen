# Ark module screens: arcana, nature, exploration and habitation

> **Replaced by [`ark-modules-v2.md`](ark-modules-v2.md) (25 September 2026).** The Ark's first version (the module screens with batches, projects and journeys; the Ark screen replaces them) was removed: each module now gives a global effect to its team from its place in the Ark. This page is kept as the record of what existed; the companion no longer implements it.

Four placed modules show a read-only status screen through a normal empty-main-hand use. The server reads the current player's team campaign, checks the clicked block, reach and spectator mode, and sends one bounded S2C snapshot to the interacting player only; the client drops a snapshot addressed to someone else. This is a snapshot at opening; use the module again to refresh it after progress changes. Material possession is not evidence. The existing `Campaigns.Campaign.completed` observations, `ArkCommissioning.STEPS` and current partial deposit map remain authoritative; no second ledger or offline work is introduced.

Crouching and using one of these modules with an empty main hand is the deliberate local deposit gesture. Arcana accepts only step 1, nature step 2, habitation step 4 and exploration step 5 of the existing zero-based six-step list. A future, completed or blocked step reports why it took nothing. For the current eligible step, the journal enters the same `ArkActions`/`ArkCommissioning.deposit` transaction as logistics: exactly one loaded controller whose volume includes the module, all six loaded physical modules, current team identity, reach, non-spectator mode and the player's own inventory are required. Only the missing amount of that step is consumed, including offhand supplies; partial deposits persist and replay takes nothing. Unknown chunks, missing modules or ambiguous controllers cannot authorize a deposit. No remote inventory, second ledger, reward, buff, passive work or automatic final activation is involved. The final crouched controller gesture remains separate.

Each module lists its own evidence. Arcane reads `spectral_archive`, `sealed_memory` and `atlas_voices`. Nature reads `nursery_protocol`, `pollinator_treaty` and `renewal_engine`. Exploration separates the `horizon_survey` project from team journeys `aether_arrival`, `twilight_arrival`, `bumblezone_arrival` and `end_arrival`; crafted samples never appear as visited routes. Habitation reads `travellers_table`, `travelling_pantry` and `settlement_supply`. Every module also lists whether its own module project was delivered.

The status word distinguishes an upcoming (`waiting`), current (`delivering`, or `blocked` without act V and all six module projects), delivered or archived batch. An upcoming batch shows its static cost with nothing stored. The current batch shows credited quantities from the team's partial deposit map. A delivered batch reads as full. The final ending remains a separate recorded milestone. On interaction only, the existing bounded inverse controller scan reports a nearby controller, missing modules or unloaded/ambiguous space; it does not load chunks. The screen remains readable without a controller.

## Status screen (playtest 2026-09-25)

Elias, after playing: "the modules are like books to read with strange data; not much makes sense". The former vanilla `BookViewScreen` pages (documented/pending projects, batch sentences, materials, controller coordinates, service instructions) are replaced by `client/ArkModuleScreen`, readable at a glance:

- **Header:** the module's own block item and name, and one status line, for example `Lote 2 de 6 · entregando` / `Batch 2 of 6 · delivering`, coloured by state (blue delivering, gold delivered, red blocked, grey waiting or archived).
- **Batch materials:** each item in a vanilla slot with its name, `1 / 2` and the experience bar as the progress bar.
- **Projects** with a `done / total` count: each project's own item (the first ENTRELUMEN item it takes; a module project shows its module), its Atlas name and the vanilla checkmark or an empty inset box. What is still missing sorts first; campaign order holds inside each group.
- **Witnessed journeys** (exploration): four dimension icons, each the icon its own mod gives the dimension (the Aether's "The Aether" advancement `aether:aether_portal_frame`, the Twilight Forest root advancement `twilightforest:twilight_portal_miniature_structure`, the Bumblezone root advancement `the_bumblezone:honeycomb_brood_block`, vanilla's End root and the pack's End quest `minecraft:end_stone`), checked when witnessed and greyed when not. Glowstone, an oak sapling and a honeycomb block stand in when a mod is absent. Names show on hover.
- **Ark and service rows:** one controller row (assembled, missing N modules, not loaded, several controllers, none nearby, or the Ark active) and one service row (forge restoration, restoration site, chart room or lodging state). The former long instructions and coordinates moved to their hover text.
- **One flavor line** per module and evidence level (empty, partial, recorded), never longer than one line, then the next action: crouch-use to deliver, which batch opens this one, or why it is blocked.

Delivery is unchanged: crouching and using the module with an empty main hand delivers, exactly as before; the screen only says so. The snapshot (`JournalBookNetwork.Snapshot`, payload `entrelumen:journal_book`, registrar version 2) now carries the status, flavor, optional hint and up to 24 typed rows (item icon, optional label, `done / total`, up to 8 hover lines) within the same 32 KiB bound. The server resolves every icon against the item registry and falls back to paper, so the client never meets an unknown item. Rows are sorted and labelled on the server; the client only lays them out. The body scrolls with the wheel or the arrow and page keys when the window is short (the Arcane screen is 266 GUI pixels tall; GUI scale 3 at 768 px leaves 256); Done and Escape close it.

## Tests

JUnit `ArkFieldJournalsTest`: evidence-dependent flavor, the team's independent record, upcoming/current/delivered/blocked/archived status and hint, missing-first project order and icons (each an item the project takes or unlocks), dimension icons with vanilla stand-ins, every controller state of the Ark row, snapshot bounds and validation, and every screen text present in `en_us` and `es_es` with flavor lines of at most 40 characters. GameTests read all four module kinds without mutation, check team identity, translated status, an assembled Ark row and registered icons, round-trip the codec and reject an oversized payload; deposit tests are unchanged. Installed client and full-pack behavior are separate acceptance steps.
