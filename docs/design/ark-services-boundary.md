# Practical Ark services: implementation boundary

Engineering is an implemented material repair workshop. Arcana is an implemented compound-book library. Both require a complete physical Ark, operate only on deliberate interaction, preserve free gifts and do not award campaign progress. Their bounded evidence and limitations are in `ark-workshop-magic-runtime.json` and `arcane-building-runtime.json`.

The remaining four modules retain their current diagnostics, team journals and recoverable commissioning deposits. Those interactions do not yet satisfy the acceptance requirement for six practical endgame benefits. The following are design candidates, not committed gameplay or implemented features:

| Module | Candidate and intended contribution | Evidence required before selection |
| --- | --- | --- |
| Nature | Propagate an already acquired crop specimen using its native materials; keep farming infrastructure useful | Audit MA seed tiers, native reprocessing, alternative acquisition and cost/output loops. Do not adopt unbounded or generic seed duplication, NBT copying or bee-genetics copying. |
| Exploration | Expedition port connecting aircraft operations between established Arks | Check existing Waystones Warp Plates with pinned Immersive Aircraft first; require preservation of passengers, cargo and native fuel, safe landing, loaded endpoints and cancellation without partial relocation or duplication. The existing signal station already binds compasses; another generic locator adds no distinct service. |
| Logistics | A paid physical parcel between explicitly linked Ark endpoints | Audit overlap with existing dimensional storage, registered endpoints, destination capacity, restart recovery and atomic inventory ownership before introducing persistent transfers. Never silently load an offline destination or pull from arbitrary remote inventories. |
| Habitation | A temporary expedition respawn with deliberate restoration of the player's prior home | Audit vanilla bed/anchor invalidation, dimensions, logout and death hooks. Do not alter graves, inventory recovery or hunger merely to create demand for the service. |

Astra's design review retained these as exploratory options. No transport, seed, respawn or persistence code was added in this delivery. Prefer native mechanisms when they fulfill a distinctive player need. Each selected service still needs its own constrained implementation and runtime proof; six generic buffs or repeated journal buttons are not a substitute.
